# Базы данных — PostgreSQL

Учебный проект для Windows PowerShell, VS Code, Git, Docker Desktop и DBeaver. Работаем в ветке `main`. Docker Desktop должен быть запущен в режиме Linux containers.

## Первый запуск в аудитории

```powershell
cd D:\students
git clone https://github.com/nlobro/basework.git
cd basework
.\scripts\start-class.ps1
```

Перед первым коммитом проверьте автора: `git config user.name` и `git config user.email`.
При необходимости задайте только для этого репозитория:

```powershell
git config --local user.name "nlobro"
git config --local user.email "ВАШ_GITHUB_EMAIL_ИЛИ_NOREPLY"
```

Замените значение email своим адресом из настроек GitHub. На общих компьютерах не используйте `--global`.
Если PowerShell запрещает локальные скрипты, после просмотра файлов разрешите их в текущем терминале: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`. Политика организации может запрещать изменение.

Повторное занятие в сохранившейся копии: `.\scripts\start-class.ps1`.
При локальных изменениях скрипт остановится: сначала сохраните их коммитом. Ошибку авторизации Git решайте интерактивным входом через Git Credential Manager; токены в файлы не записывайте.

## Подключение через DBeaver

| Параметр | Значение |
| --- | --- |
| Host | 127.0.0.1 |
| Port | 5432 |
| Database | postgres |
| Username | postgres |
| Password | postgres |

`postgres/postgres` — общие учебные значения. Порт доступен только с локального компьютера. После старта подождите несколько секунд до готовности PostgreSQL.
Имя контейнера — `postgres-db`, проект Compose — `postgres-study`. Если порт или контейнер уже занят, выясните причину; не удаляйте чужие контейнеры.

## Выполнение SQL

Сохраните SQL-файл в UTF-8, например `sql/test.sql` с текстом `SELECT 1;`.

```powershell
.\scripts\run-sql.ps1 .\sql\test.sql
```

Скрипт останавливается при первой ошибке SQL; предыдущие успешные команды могут быть уже выполнены. Для атомарной работы используйте транзакцию в самом SQL.

Ручной вход:

```powershell
docker ps
docker exec -it postgres-db psql -U postgres -d postgres
```

В psql: `\dt` — таблицы, `\q` — выход.

## Сохранение работы

```powershell
git status
git add .
git commit -m "Описание изменений"
git push
```

Завершение занятия с сохранением и удалением учебной базы:

```powershell
.\scripts\finish-class.ps1 -Message "Сделано ДЗ 3"
```

Без параметра сообщение — «Работа на занятии». Если изменений нет, новый коммит не создаётся, push всё равно выполняется.
Если push отклонён, база и локальная папка сохраняются. Исправьте проблему, при необходимости получите и объедините удалённые изменения, затем повторите.

## Перед уходом

**СНАЧАЛА PUSH, ТОЛЬКО ПОТОМ УДАЛЕНИЕ.**

1. Сохраните SQL, данные для восстановления и задания в файлы; выполните `git push`.
2. Проверьте последний коммит на GitHub. Чистый `git status` сам по себе не доказывает отправку.
3. Выполните `docker compose down -v`, если не использовали finish-class. Команда безвозвратно удаляет базу в volume проекта; образ PostgreSQL остаётся.
4. Закройте файлы, выйдите из папки и удалите локальную копию через Проводник только после проверки GitHub.
5. При необходимости удалите подключение DBeaver.
6. Выйдите из GitHub в VS Code и браузере, удалите свою сохранённую авторизацию из Git Credential Manager на общем ПК. Если входили через GitHub CLI, выполните `gh auth logout`.

Скрипт finish-class удаляет volume сразу после успешного push; локальную папку он не удаляет.

## Где хранить файлы

- `homework/dz1/`, `homework/dz2/` — домашние задания.
- `sql/` — SQL-скрипты, схема и исходные данные для восстановления.
- `diagrams/` — ER-диаграммы.
- `scripts/` — запуск, сохранение и выполнение SQL.

PostgreSQL хранит результат выполнения SQL временно. GitHub хранит отправленные SQL-файлы и остальные материалы. Изменения, сделанные только в DBeaver, сохраняйте в SQL-файлы перед завершением занятия.
